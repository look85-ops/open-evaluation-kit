# Open Evaluation Kit

Открытый набор проверок для AI в обучении.

## Зачем он нужен

AI может написать убедительный сценарий, дать красивую обратную связь или уверенно сформулировать рекомендацию и при этом ошибиться в цели, фактах или последствиях. Evaluation Kit помогает проверять не «насколько хорошо звучит ответ», а можно ли принять его в рабочем процессе.

Подходит для:

- AI-ассистентов методиста;
- генерации сценариев занятий и учебных материалов;
- анализа обратной связи после обучения;
- тьюторов и симуляторов;
- внутренних L&D-пайплайнов, где результат проверяет человек.

## Быстрый старт

1. Выбери одну конкретную задачу и один результат AI.
2. Если исходные данные рабочие, замени их синтетическим или обезличенным примером.
3. Заполни `evaluation-card-template.md`.
4. Проверь результат по `rubric.md`.
5. Зафиксируй решение человека: `accept`, `clarify` или `reject`.
6. Добавь одно следующее действие и критерий его готовности.

Не проверяй «всю систему» сразу. Один хорошо описанный тест полезнее общего впечатления.

## Рубрика

| Область | Что проверяем |
|---|---|
| Цель | Связан ли результат с задачей и аудиторией? |
| Методика | Есть ли цель, практика, обратная связь и перенос? |
| Факты | Есть ли источник или честная пометка «гипотеза»? |
| Обратная связь | Помогает ли она сделать следующую попытку? |
| Ограничения | Видны ли пробелы данных и альтернативные объяснения? |
| Безопасность | Не раскрываются ли лишние персональные данные? |
| Human review | Понятно ли, где решение подтверждает специалист? |
| Воспроизводимость | Повторяется ли проверка на другом примере? |

Статусы:

- `PASS` — есть наблюдаемое основание принять критерий;
- `FAIL` — критерий нарушен;
- `REVIEW` — данных недостаточно, нужно решение человека.

## Как выглядит карточка

```yaml
test_id: feedback-001
task: "Сформулировать развивающую обратную связь"
context: "Синтетический пример для руководителя"
expected_result: "Конкретная обратная связь и следующий шаг"
status: REVIEW
evidence: "В ответе есть наблюдение и предложение следующего действия"
limitation: "Не проверена применимость к реальному разговору"
human_decision: clarify
next_action: "Методист проверяет формулировку на ролевой репетиции"
```

## Важные правила

- Не ставь проценты уверенности, если способ расчёта не определён.
- Не называй fallback искусственным интеллектом.
- Не ставь `PASS` без цитаты, правила, расчёта или другого проверяемого основания.
- Если критерий нельзя проверить, ставь `REVIEW`, а не угадывай.
- Не отправляй в тесты персональные данные, закрытые документы и рабочие секреты.

## Файлы

- `evaluation-card-template.md` — копируемая карточка одного вывода.
- `rubric.md` — расширенная рубрика PASS/FAIL/REVIEW.

## Связь с практикой

Этот набор можно использовать отдельно или как последний этап мультиагентного процесса: Eval Owner фиксирует доказательства, ограничения и решение, которое должен принять человек.
